5.http协议

	(1) HTTP (超文本传输协议HyperText Transfer Protocol)
	
		是应用层的面向对象协议，设计目的是确保客户端与服务器之间的通信，是互联网上最常用的协议之一。
		
			核心：
				通信规则
				请求报文和响应报文
	
	(2) 通信流程：
		- **建立连接**：客户端与服务器之间建立连接。在传统的 HTTP 中，这是基于 TCP/IP 协议的。最近的 HTTP/2 和 HTTP/3 则使用了更先进的传输层协议，例如基于 TCP 的二进制协议（HTTP/2）或基于 UDP 的 QUIC 协议（HTTP/3）。
		- **发送请求**：客户端向服务器发送请求，请求中包含要访问的资源的 URL、请求方法（GET、POST、PUT、DELETE 等）、请求头（例如，Accept、User-Agent）以及可选的请求体（对于 POST 或 PUT 请求）。
		- **处理请求**：服务器接收到请求后，根据请求中的信息找到相应的资源，执行相应的处理操作。这可能涉及从数据库中检索数据、生成动态内容或者简单地返回静态文件。**（服务端）**
		- **发送响应**：服务器将处理后的结果封装在响应中，并将其发送回客户端。响应包含状态码（用于指示请求的成功或失败）、响应头（例如，Content-Type、Content-Length）以及可选的响应体（例如，HTML 页面、图像数据）。
		- **关闭连接**：在完成请求-响应周期后，客户端和服务器之间的连接可以被关闭，除非使用了持久连接（如 HTTP/1.1 中的 keep-alive）。

	(3) 请求数据格式
		请求行：请求方法 [空格] URL [空格] 协议版本 [回车符][换行符]
		请求头部：头部字段名 [:] 值 [回车符][换行符]
		请求头部：头部字段名 [:] 值 [回车符][换行符]
		请求头部：头部字段名 [:] 值 [回车符][换行符]
		.... （请求头有多组）
		空行：[回车符][换行符]
		请求体：（客户端传递的数据）

	(4) 响应数据格式
	
		状态行：协议版本 [空格] 状态码 [空格] 状态描述 [回车符][换行符]
		响应头部：头部字段名 [:] 值 [回车符][换行符]
		响应头部：头部字段名 [:] 值 [回车符][换行符]
		响应头部：头部字段名 [:] 值 [回车符][换行符]....（响应头有多组）
		空行：[回车符][换行符]
		响应体：（服务器返回的数据）

	(5) 请求方法：
	
		get: 查询
		
			没有请求体。数据放url后面传输。长度有限制(不要大于2Kb)。不安全。是幂等。
		
		post: 添加
		
			有请求体。没有大小限制。支持上传文件。不是幂等。安全。
		
		put: 修改
			有请求体。没有大小限制。支持上传文件。是幂等。安全。
		
		delete: 删除
			没有请求体。数据放url后面传输。长度有限制(不要大于2Kb)。不安全。是幂等。
		
		...

	
	(1) 请求状态码：
	
		1** 信息
		
		2** 成功
		
			200 成功
		
		3** 重定向
		
			302 重定向
		
		4** 客户端错误
		
			400 参数错误
			403 无权访问
			404 资源找不到，一般路径错误
			405 请求方法不对
			
		
		5** 服务端错误
			500 服务器端有异常
			502 网关错误
			503 服务不可用

7.核心注解：

	@SpringBootApplication
		声明一个SpringBoot应用主程序。

	@Controller  声明一个控制器组件

	

	@RestController
		声明一个控制器组件。并纳入IOC容器里被管理。
		组合注解： @Controller + @ResponseBody
		
	@RequestMapping
		声明一个路径映射。用于客户端的访问
		
		精确匹配：
			@RequestMapping(value = {"/user/login"})
			@RequestMapping(value = {"/user/register"})
		模糊匹配：
			通过 `*` 或 `**` 通配符匹配多个相似路径，适用于批量映射场景：
				- `/*`：匹配**单层**任意字符串（仅一级路径）
				- `/**`：匹配**任意层**任意字符串（多级路径）
			例如：
				@RequestMapping("/product/**")   匹配多级路径
				@RequestMapping("/product/*")    匹配一级路径
				
		注解位置：
			注解放在类上和方法上时，父路径+子路径=完整路径
	
		请求方式限制
			@RequestMapping(value = "list", method = RequestMethod.GET)  //只能发送get请求
			
			@RequestMapping(value = "list", method = {RequestMethod.GET,RequestMethod.POST}) //支持get或post,否则：405 Method Not Allowed
	
			请求方法：
				public enum RequestMethod {
				  GET, HEAD, POST, PUT, PATCH, DELETE, OPTIONS, TRACE
				}
	
		简便注解：
			@GetMapping  只支持get请求	
			@PostMapping  只支持gpost请求
			@PutMapping   只支持put请求
			@DeleteMapping  只支持delete请求
			
				关键提醒：快捷注解**仅能标注在方法上**，无法用于类级别；类级别仍需使用 `@RequestMapping` 配置通用前缀。
	
		映射冲突：
			请求方法和请求路径不同同时一致。否则声明上会出现冲突。
	
	@RequestParam(value="Phone",required = true,defaultValue = "13199999999")
		value用来映射参数名称。当请求参数名称与方法参数名称不一致时，可以用于接收参数。
		required = true 表示必须传递请求参数。400 Bad Request
		defaultValue = ""  用于设置默认
		
		
		一个参数名多个参数值：
			    //   http://localhost:8080/user/hobby?hbs=吃&hbs=喝&hbs=玩
				@GetMapping("hobby") //只支持get请求
				public String hobby(String[] hbs) {  //直接定义数组即可
					System.out.println("hbs = " + hbs);
					return "-----hbs="+hbs;
				}

				@GetMapping("hobby") //只支持get请求
				public String hobby(@RequestParam List<String> hbs) {  //必须增加@RequestParam
					System.out.println("hbs = " + hbs);
					return "-----hbs="+hbs;
				}

	@PathVariable 路径接收参数	
	
		@RequestMapping(value="{id}")
		public SysUser getSysUserById(@PathVariable Long id)  //路径占位符名称和方法参数名称【一样】，增加注解即可

		@RequestMapping(value="{userId}")
		public SysUser getSysUserById(@PathVariable("userId") Long id)  //路径占位符名称和方法参数名称【不一样】，需要通过注解value起别名，与占位符名称一致。
	
		@PathVariable(required = true)   //站位付参数必须传递
	
	


	@RequestBody  获取请求体数据。post和put带有请求体的。get和delete是没有请求体的。
		注意：delete在http协议中表示有请求体。但是浏览器或框架一般不支持。
	
	


	@ResponseBody  响应体。数据要以响应体方式返回。
	
	
	@RequestHeader 用于接收请求头
		@RequestHeader(value="Content-Type",required=true) 
	
	@CookieValue("token")

12.共享域 

	用来共享数据。因为转发或重定向都需要跳转多个资源来处理同一个请求。
	
	A -> B -> C  
	
	A、B、C 都需要同一个数据时，如何获取？
	
	
	采用web开发共享域：有3个
	
	request域：HttpServletRequest
	
		在同一次请求中有效
	
	session域：HttpSession      30分钟
	
		在同一个客户端(登录->注销)，多次请求中有效
		
	application域：ServletContext
	
		在不同客户端，不同的请求中都有效
		整个应用唯一的，大家可以共享。
		
	推荐使用顺序（范围从小->大）：  request > session > application 
	
	后期：分布式系统开发，集群环境下数据共享。这3个域都不用。会采用redis做数据共享。

	
	客户端共享数据技术：Cookie [不安全,客户端,数据小,容易丢(浏览器清理缓存),被禁用]
	服务器共享数据技术：request、session、application [安全,服务器端,数据量没有限制]
	
	cookie(客户端)和session(服务器端)都用用于跟踪用户状态。(你是谁)

15.扩展ResponseEntity(了解)  

	org.springframework.http.HttpStatus   常用状态码


	@RestController
	@RequestMapping("/response-entity")
	public class ResponseEntityController {

		// 示例1：返回自定义状态码+统一Result类（最常用）
		@GetMapping("/user/{id}")
		public ResponseEntity<Result> getUser(@PathVariable Long id) {
			// 模拟查询用户
			if (id == 1) {
				// 成功：200状态码 + Result数据
				Result successResult = Result.success("查询成功", "用户ID：1的信息");
				return new ResponseEntity<>(successResult, HttpStatus.OK);
			} else {
				// 失败：404状态码 + Result提示
				Result failResult = Result.fail(404, "用户不存在");
				return new ResponseEntity<>(failResult, HttpStatus.NOT_FOUND);
			}
		}

		// 示例2：自定义响应头+文本响应
		@GetMapping("/text")
		public ResponseEntity<String> returnText() {
			HttpHeaders headers = new HttpHeaders();
			headers.add("Custom-Header", "MyCustomValue"); // 自定义响应头
			// 返回：文本内容 + 响应头 + 200状态码
			return new ResponseEntity<>("ResponseEntity返回的文本", headers, HttpStatus.OK);
		}
	}

16.RESTFul(表述性状态转移)

	RESTful 接口设计的 4 个核心原则，缺一不可：

		1. **资源唯一标识**：每个 URL（URI）只代表一种 “资源”（比如用户、商品），URL 中只包含**名词**（如`/user`），不包含动词（如`/getUser`）；
		2. **HTTP 方法表语义**：客户端通过 GET/POST/PUT/DELETE 这 4 个 HTTP 动词，对服务端的资源做 “增删改查” 操作，而非在 URL 中体现操作：
		   - GET：获取资源（查询）；
		   - POST：新建资源（新增）；
		   - PUT：更新资源（修改）；
		   - DELETE：删除资源（删除）；
		3. **数据格式标准化**：资源的传递 / 返回格式用 JSON（主流），前后端数据交互格式统一；
		4. **无状态交互**：客户端的每次请求都包含服务端处理该请求的所有信息，服务端无需保存 “会话状态”（比如用户登录状态），降低系统复杂度。

	1 异常处理
		
		try - catch - finally - throw - throws
		
		Error类型异常，无法进行try-catch处理的。
		Exception类型异常，可以进行异常处理的。要么try-catch进行捕获，要么throw抛出去。
		
		Throwable
			- Error
				- VirtualMachineError
					- StackOverflowError 		栈内存溢出
					- OutOfMemoryError 			堆内存溢出			
			- Exception
				- RuntimeException 				运行期异常，写代码、编译代码时，IDEA不提示我们异常处理。代码运行起来可能抛出异常。
					- NullPointerException		空指针异常
					- ArithmeticException		算术异常
					... 
				- IOException 					编译期异常。受检查异常。写代码、编译代码时，IDEA会提示我们进行异常处理。
				...
	
		SpringMVC提供声明式异常统一处理机制。
			@RestControllerAdvice（全局异常处理器）+ @ExceptionHandler（异常匹配方法）
			
		总结：	
			1. 声明式异常处理核心：通过`@RestControllerAdvice`（全局拦截）+`@ExceptionHandler`（匹配异常类型），将异常处理逻辑抽离；
			2. 优先级规则：精准异常处理方法（如处理 NullPointerException）> 兜底异常处理方法（处理 Exception）；
			3. 核心价值：解耦业务与异常代码、统一异常提示规则、屏蔽底层报错、提升系统安全性和可维护性；
			4. 实战要点：异常处理方法需返回统一响应类（如 Result），仅向前端返回 “状态码 + 友好提示”，后端保留异常日志用于排查。

19.MVC 与 三层架构

	MVC： (Model - View - Controller)
	
		针对于客户端与后端表现层一种交互处理程序设计模式。
		
		Model : 模型 （数据模型，service dao pojo）
		
		View: 视图 （html vue  手机app  微信小程序）		
		
		Controller: 控制器 ( 接收数据 、 执行模型处理 、 直接返回数据或转发重定向)
		
		**Web 场景下的数据流程**

			浏览器发起请求 → Controller 接收请求 → 调用 Model 处理业务 / 操作数据 → Model 返回处理结果 → Controller 封装响应 → View 展示数据给用户
	
	三层架构：
	
		控制器层/表现层：控制器 ( 接收数据 、 执行模型处理 、 直接返回数据或转发重定向) ，调用业务层      XxxController
		
		业务逻辑层： 负责业务逻辑处理。(例如：下单业务（保存订单，减库存，发送短信，送积分等）) ，调用持久化层      XxxService/XxxServiceImpl
		
		数据持久化层：对数据CRUD操作。   XxxDao/XxxDaoImpl   POJO（DO/DTO）
		
			**三层架构数据流程（Java 后端）**

			前端请求 → 表现层（Controller）接收 → 调用业务逻辑层（Service）处理业务 → 业务层调用数据访问层（DAO）操作数据库 → DAO 返回数据给业务层 → 业务层处理后返回给表现层 → 表现层封装响应返回给前端
	

20.Spring

	(1) IOC:

24.MyBatis 多表关联

	表的数据关系有几种？
		一对一: 在一对多的基础上，给多的一端外键设置unique约束
		
		一对多：PK   FK
		
		多对一：PK   FK
		
		多对多： 由两个一对多或两个多对一组成的。因为多对多需要建一张中间表描述数据关系。

	MyBatis关联关系
	
		对一：在查询一端时，另一端只能有一个数据被关联查询。一对一，多对一
		
		对多：在查询一端时，另一端可以查询多条数据。一对多，多对多 

	关联关系-对一 案例 
	
		实体之间关系：
			@Data
			public class Order {
				private Integer orderId;
				private String orderName;
				private Customer customer;// 体现的是对一的关系
			}
			
			@Data
			public class Customer {
				private Integer customerId;
				private String customerName;
			}
		
		接口声明：
			@Mapper
			public interface OrderMapper {

				//业务需求：查询订单的同时，需要查询关联用户   对一关联操作
				Order selectOrderWithCustomer(Long orderId);
			}
		
		接口映射：
			<mapper namespace="com.atguigu.mybatis.mapper.OrderMapper">

				<resultMap id="OrderResultMap" type="com.atguigu.mybatis.entities.Order">
					<id column="order_id" property="orderId" ></id>
					<result column="order_name" property="orderName"></result>

					<!--关联属性  对一关联-->
					<association property="customer" javaType="com.atguigu.mybatis.entities.Customer">
						<id column="customer_id" property="customerId" ></id>
						<result column="customer_name" property="customerName"></result>
					</association>
				</resultMap>

				<select id="selectOrderWithCustomer" resultMap="OrderResultMap">
					SELECT
						t_order.order_id,
						t_order.order_name,
						t_customer.customer_id,
						t_customer.customer_name
					FROM t_order
							 left join t_customer on t_order.customer_id = t_customer.customer_id
					where order_id = #{orderId}
				</select>

			</mapper>

	关联关系-对多 案例
	
		实体之间关系：
			@Data
			public class Customer {
				private Integer customerId;
				private String customerName;
				private List<Order> orderList;// 体现的是对多的关系
			}
			
			@Data
			public class Order {
				private Integer orderId;
				private String orderName;
			}
		
		接口声明：
			@Mapper
			public interface CustomerMapper {

				//查询客户信息，同时查询关联订单集合
				Customer selectCustomerWithOrderList(Integer customerId);
			}
		
		接口映射：
			<mapper namespace="com.atguigu.mybatis.mapper.CustomerMapper">

				<resultMap id="CustomerResultMap" type="com.atguigu.mybatis.entities.Customer">
					<id column="customer_id" property="customerId"></id>
					<result column="customer_name" property="customerName"></result>

					<!--
						对多关联
					-->
					<collection property="orderList" ofType="com.atguigu.mybatis.entities.Order">
						<id column="order_id" property="orderId"></id>
						<result column="order_name" property="orderName"></result>
					</collection>
				</resultMap>

				<select id="selectCustomerWithOrderList" resultMap="CustomerResultMap">
					select t_customer.customer_id,
						   t_customer.customer_name,
						   t_order.order_id,
						   t_order.order_name
					from t_customer
							 left join t_order on t_customer.customer_id = t_order.customer_id
					where t_customer.customer_id = #{customerId}
				</select>

			</mapper>



	上述，对一关联和对多关联采用连接语句，是立即查询方式。
	特别对多关联查询时，有时只需要一的一端数据，不需要多的一端数据，但是多的一端数据也被查询了，会影响性能。
	
	解决问题：可以采用分步查询。可以使用立即，也可以使用延迟加载。两种都支持。

		- 关联关系-分步查询(默认立即加载)
		
			1.接口声明
				Customer selectCustomerWithLazyOrderList(Integer customerId);
				
			2.接口配置 
				<resultMap id="CustomerWithLazyOrderListResultMap" type="com.atguigu.mybatis.entities.Customer">
					<id column="customer_id" property="customerId"></id>
					<result column="customer_name" property="customerName"></result>

					<!--
						通过select属性指定辅助接口，帮我们查询关联数据，封装orderList属性值。column="主键字段名称"
					-->
					<collection property="orderList" select="com.atguigu.mybatis.mapper.OrderMapper.selectOrderListByCustomerId"
								column="customer_id"></collection>
				</resultMap>

				<select id="selectCustomerWithLazyOrderList" resultMap="CustomerWithLazyOrderListResultMap">
					select t_customer.customer_id,
						   t_customer.customer_name
					from t_customer where customer_id=#{customerId}
				</select>
				
			3.辅助接口声明：
				List<Order> selectOrderListByCustomerId(Long customerId);
				
			4.辅助接口配置：
				<select id="selectOrderListByCustomerId" resultType="com.atguigu.mybatis.entities.Order">
					SELECT
						t_order.order_id,
						t_order.order_name
					FROM t_order where customer_id=#{customerId}
				</select>
				

		- 关联关系-延迟加载(<=3.4.1 无需配置aggressiveLazyLoading=false)
			
			mybatis.configuration.lazy-loading-enabled=true

26.Spring 进阶：AOP & 声明式事务

	IoC和AOP是Spring框架两个核心模块。

	(1) AOP（ Aspect Oriented Programming 面向切面编程）
	
		AOP是基于IoC容器。对程序功能进行功能扩展。解决重复代码问题。实现业务代码和非业务代码解耦。
	
	(2) 常用切面：
	
		非业务代码，重复代码，定义成一个一个的切面程序。
			例如：日志、事务、权限、数据校验、统计等

	(3) 代理模式：
	
		A -> C(代理) -> B(目标)
	
		1) 静态代理：
		
			代理类需要我们开发的。


		2) 动态代理：
		
			① JDK动态代理：
				基于接口代码方式。代理类和目标类都实现同一个接口。基于反射机制生成代理类。类名规则  "$Proxy前缀 + 数字"
				核心API:
					java.lang.reflect.Proxy
					java.lang.reflect.InvocationHandler
					
				代码案例：
				
					A -> C(代理-h(InvocationHandler.invoke())) -> B(目标)
				
				// ========== 1. 业务接口（JDK动态代理必须依赖接口） ==========
				public interface UserService {
					boolean login(String username, String password);
				}
				
				// ========== 2. 目标类（实现接口，仅做核心业务） ==========
				public class UserServiceImpl implements UserService {
					@Override
					public boolean login(String username, String password) {
						System.out.println("目标方法正在登录中....");
						// 核心业务：登录校验
						return "admin".equals(username) && "123456".equals(password);
					}
				}
				
				public class JDKProxyTest {
					public static void main(String[] args) {
						//1.创建目标对象
						UserService userService = new UserServiceImpl(); //通过接口实现类创建目标对象

						//2.创建代理对象
						UserService userServiceProxy = (UserService) Proxy.newProxyInstance(
								userService.getClass().getClassLoader(), //类加载器
								userService.getClass().getInterfaces(), //目标对象接口。代理类和目标类实现同一个接口
								(proxy, method, methodArgs) -> { //InvocationHandler对象
									System.out.println("开始登录了"); //日志：非核心业务代码

									Object result = method.invoke(userService, methodArgs); //调用目标             相当于 userService.login("admin","123456")

									System.out.println("等了完成了"); //日志：非核心业务代码

									return result;
								}
						);


						//3.调用代理对象
						//userService.login("admin","123456");  //直接调用目标对象方法，只能执行核心业务代码。要想执行扩展代码，需要调用代理
						boolean flag = userServiceProxy.login("admin", "123456"); //调用代理类方法-> 调用InvocationHandler接口方法实现
						System.out.println("flag = " + flag);
					}
				}
				
				
				
			② Cglib动态代理：
				基于继承实现方式。代理类是目标类子类。代理类是通过第三方组件，字节码生成工具动态生成的。  内部类形式
		
				导包：
					<dependency>
						<groupId>cglib</groupId>   <!-- 核心代理库 -->
						<artifactId>cglib</artifactId>
						<version>3.3.0</version>    <!-- 推荐使用最新稳定版 -->
					</dependency>
					
				// ========== 1. 目标类（无需实现接口，仅做核心业务） ==========
				public class UserService {
					public boolean login(String username, String password) {
						System.out.println("正在登录中...");
						// 核心业务：登录校验
						return "admin".equals(username) && "123456".equals(password);
					}
				}
				
				public class CglibTest {
					public static void main(String[] args) {
						//1.创建目标对象
						UserService userService = new UserService();

						//2.创建代理对象,代理类是目标类的子类
						UserService proxy = (UserService)Enhancer.create(UserService.class,
								(MethodInterceptor)(proxyObj, method, argsArr, methodProxy) ->{

									System.out.println(method.getName()+"方法开始执行了...."); //扩展代码

									Object result = method.invoke(userService, argsArr); //调用目标对象方法

									System.out.println(method.getName()+"方法结束执行了...."); //扩展代码

									return result;
								});

						//3.调用代理对象方法
						boolean flag = proxy.login("admin", "123456");
						System.out.println("flag = " + flag);
					}
				}

	(4) AOP核心概念：
	
		横切关注点：
		
			横切面：日志、事务、权限、数据校验、统计等。需要解决的共性问题。

		通知(增强)：
		
			编写非业务逻辑的代码。一般代码写在五种通知中：
			
				* 前置通知(@Before)：在被代理的目标方法前执行

				* 返回通知(@AfterReturning)：在被代理的目标方法成功结束后执行（**寿终正寝**）

				* 异常通知(@AfterThrowing)：在被代理的目标方法异常结束后执行（**死于非命**）

				* 后置通知(@After)：在被代理的目标方法最终结束后执行（**盖棺定论**）

				* 环绕通知(@Around)：使用try...catch...finally结构围绕整个被代理的目标方法，包括上面四种通知对应的所有位置

		连接点 joinpoint
		
			连接点，就是问题代码所在行或方法位置。

		切入点 pointcut	
			用切入点表达式匹配的连接点。真正需要执行扩展代码的位置。

		切面 aspect
		
			切面是被解决的一个一个问题。一般需要编写切面类，类中声明通知方法。

		目标 target：
			核心业务代码。被扩展功能的对象。
			
		代理 proxy ：
			用于执行扩展 代码的类。可以采用JDK动态代理或Cglib动态代理。
		
		织入 weave：
			在目标方法执行的过程中，之前，之后，有异常时，执行扩展代码的过程。

		是专业AOP框架。可以简化AOP开发。

		@EnableAspectJAutoProxy(proxyTargetClass = false)  //默认true表示采用cglib动态代理。  这个注解失效。
	
		# application.properties 需要使用配置文件的方式才会生效。
		spring.aop.proxy-target-class=false # 覆盖默认值true，强制有接口时使用JDK动态代理
		
			特殊情况依然失效：
				- 目标类实现的是**非公开的内部接口**（即接口未使用 `public` 修饰）；
				- 目标类本身已是代理对象（例如项目存在循环依赖，导致 Spring 提前为该类生成了代理）；
				- 目标类包含 `final` 修饰的方法（尽管 JDK 代理本身不影响 final 方法的执行，但 Spring 会优先选择 CGLIB 代理来兜底处理）。

	(9)	事务切面：
	
		1) 什么是事务：多个操作作为一个整体，要么都成功，要么都失败。
		
		2) 事务作用：保证数据一致性。
		
		3) 事务特性：4个
		
			A ： 原子性
			
				多个SQL作为一个整体，不可分割。要么都成功，要么都失败。
			
			C ： 一致性
			
				数据操作结果与业务需要保存一致。
			
			I ：隔离性
			
				多个事务并发时，需要隔离操作，保证数据安全，数据一致。
			
			D ：持久性
				
				事务一旦提交，数据被永久保存。即使服务器宕机重启，数据也可以恢复。
		
		4) 隔离级别：4个级别

			1 Connection.TRANSACTION_READ_UNCOMMITTED  读未提交
				
				一个事务A读取了另一个事务B未提交事务的数据，可能出现脏读情况。
			
			2 Connection.TRANSACTION_READ_COMMITTED  读已提交   oracle
			
				一个事务A读取了另一个事务B已提交事务的数据，可能出现不可重复读情况。
				
			
			4 Connection.TRANSACTION_REPEATABLE_READ 可重复读    mysql
			
				一个事务A读取另一个事务B的数据，不管事务B是否提交事务，读的结果始终是同一个。可能出现幻读问题。
			
			8 Connection.TRANSACTION_SERIALIZABLE  序列化，也叫串行化
			
				多个事务操作同一个数据，必须排队，一个一个执行。更加安全，但是效率最低。

			@Transactional(isolation = Isolation.DEFAULT)  // DEFAULT含义：与数据的隔离级别保持一致。

	
		5) 事务实现方式： 
		
			编程式事务： 需要程序员写代码
				
				java.sql.Connection.setAutoCommit(fales)  //开启事务
				java.sql.Connection.commit()              //提交事务
				java.sql.Connection.rollback()            //回滚事务
			
			声明式事务： 只需要开启事务功能，增加相关注解标识方法即可。无需编写任何代码。框架已经做好了封装。
			
				核心注解：
					@EnableTransactionManagement //开启事务功能。默认开启
					@Transactional   用于标识业务方法或类。主要用在业务逻辑层。
					
						标记在类上，就相当于每个方法都加了这个注解。
						如果类上和方法上都标记了这个注解，方法上标记的注解生效。
				
		
		6) 传播行为：org.springframework.transaction.annotation.Propagation
		
			@Transactional(propagation = Propagation.REQUIRED)      没有事务就开个事务，有事务就加入这个事务。最重要。默认值
			@Transactional(propagation = Propagation.REQUIRES_NEW)  不管有没有事务都开一个新事务
			@Transactional(propagation = Propagation.SUPPORTS)      有没有事务都行
			@Transactional(propagation = Propagation.MANDATORY)     必须有事务，我不自己创建			 
			@Transactional(propagation = Propagation.NOT_SUPPORTED) 不支持事务，有事务需要挂起
			@Transactional(propagation = Propagation.NEVER)         不能有事务，有就抛异常
			@Transactional(propagation = Propagation.NESTED)        嵌套事务，一个大事务中包含很多小的事务
			
		7) 事务超时：
		
			@Transactional(timeout = 3)    默认-1 ，永远不超时。取决于数据库的超时时间。
			
		8) 事务回滚策略：异常一定要抛出，不抛框架不会帮我们回滚事务，事务正常提交。
		
			
			事务遇到RuntimeException异常，自动回滚事务。遇到编译期异常，默认不回滚事务的。
		
			@Transactional(rollbackFor = RuntimeException.class)  默认
			
			如果希望遇到所有异常都需要事务回滚：
			
			@Transactional(rollbackFor = Exception.class) 
			
			遇到特定异常不要回滚：
			
			@Transactional(rollbackFor = Exception.class, noRollbackFor = {NullPointerException.class})
		
		9) 只读事务：
		
			@Transactional(readOnly = true)   只能执行查询，不能增删改

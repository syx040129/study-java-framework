### 第一步：工程初始化与基础配置

在动笔写任何业务逻辑之前，必须先把项目骨架和“脚手架”搭建好。

1. **创建 Spring Boot 项目**
   - 导入核心依赖（`pom.xml`）：`spring-boot-starter-web`、`spring-boot-starter-validation`、`lombok`。
2. **配置文件**
   - 编写 `resources/application.properties`，配置端口号（如 `server.port=8080`）和上下文路径等。

### 第二步：底层通用公共组件（Utils & Entity/DTO）

这是整个系统的数据载体和底层工具，后期的控制层和服务层都需要依赖它们。

1. **设计统一返回结果对象（`Result`）**
   - 优先编写 `utils/Result.java`，定义全局统一的 API 数据返回结构（包含 `code`, `message`, `data` 及 `success()`/`fail()` 静态方法）。
2. **编写数据实体与传输对象（`Entity` & `DTO`）**
   - 编写 `entity/SysUser.java`，并在此处一次性加上 **Spring Validation 参数校验注解**（如 `@NotBlank`, `@Size`, `@Pattern` 等）。
   - 编写 `entity/SysUserLoginDto.java`，定义登录所需的请求参数及校验规则。
3. **数据源 / 内存数据工具类（`SysUserDataUtil`）**
   - 编写 `utils/SysUserDataUtil.java`，准备静态 Map 模拟数据库存储，并封装底层的原生 CRUD 及登录校验逻辑。

### 第三步：数据访问层开发（DAO 层）

持久层负责直接操作数据源，不包含任何复杂的业务逻辑。

1. **编写 DAO 接口**：创建 `dao/UserDao.java`，定义增删改查及登录的底层接口方法。
2. **编写 DAO 实现类**：创建 `dao/impl/UserDaoImpl.java`，加上 **`@Repository`** 注解使其交由 Spring 容器管理，并在方法内部调用 `SysUserDataUtil` 的数据操作逻辑。

### 第四步：业务逻辑层开发（Service 层）

业务层承上启下，调用 DAO 层实现业务规则。

1. **编写 Service 接口**：创建 `service/UserService.java`，定义业务层的处理逻辑方法。
2. **编写 Service 实现类**：创建 `service/impl/UserServiceImpl.java`，加上 **`@Service`** 注解。通过 **`@Autowired`** 注入 `UserDao` 组件，实现业务方法（如删除、新增、更新校验等）。

### 第五步：表现层开发（Controller 层）

处理 HTTP 请求、校验前端参数并调用 Service 返回 JSON。

1. **用户 CRUD 控制器（`UserController`）**
   - 编写 `controller/UserController.java`，加上 **`@RestController`** 和 `@RequestMapping("/user")`。
   - 使用 `@Autowired` 注入 `UserService`。
   - 编写 RESTful 风格的接口（`@GetMapping`, `@PostMapping`, `@PutMapping`, `@DeleteMapping`），并使用 `@Valid` + `BindingResult` 进行入参校验，最后返回 `Result`。
2. **登录认证控制器（`LoginController`）**
   - 编写 `controller/LoginController.java`，处理 `/auth/login` 与 `/auth/logout`，登录成功时操作 `HttpSession` 写入用户凭证。
3. **路由跳转控制器（`WelcomeController`）**
   - 编写 `controller/WelcomeController.java`（使用普通 `@Controller`），将根路径 `/` 转发指向静态页面 `/login.html`。

### 第六步：拦截器与全局安全配置（Interceptors & Config）

为了保护核心资源接口，拦截非登录状态的非法访问。

1. **编写登录保护拦截器（`LoginProtectInterceptor`）**
   - 创建 `interceptors/LoginProtectInterceptor.java`，实现 `HandlerInterceptor` 接口。在 `preHandle` 方法中校验 Session。若未登录，直接通过 `HttpServletResponse` 手动写回 `code: 501` 的 JSON 响应并拦截。
2. **注册拦截器配置类（`WebMvcInterceptorConfig`）**
   - 创建 `config/WebMvcInterceptorConfig.java`，实现 `WebMvcConfigurer` 接口，加上 **`@Configuration`** 注解。配置需要拦截的路径（`/user/**`）和放行的路径（登录接口、静态资源）。

### 第七步：全局异常处理与收尾（Global Exception Handling）

增强系统的防御性，防止意外崩溃向前端暴露后端堆栈报错信息。

1. **编写全局异常处理器（`GlobalExceptionHandler`）**
   - 创建 `exception/GlobalExceptionHandler.java`，加上 **`@RestControllerAdvice`**。
   - 编写 `@ExceptionHandler(Exception.class)` 兜底方法，捕获所有未被处理的异常并统一包装成 `Result.fail(500, "服务器繁忙...")` 返回。

### 第八步：启动与接口自测

1. 启动 `Application.java`。
2. 使用 Postman 或 Apifox 按顺序对以下接口进行测试：
   - 测试 `POST /auth/login` 模拟登录获取 Session；
   - 测试 `GET /user/list` 验证登录保护及数据查询；
   - 测试 `POST /user` 验证参数校验失败与成功新增；
   - 直接访问受保护接口验证 `501 未登录` 拦截效果。

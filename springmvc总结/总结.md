# 总结

这份资料涵盖了 **Spring Boot / Spring MVC 开发核心知识** 与 **全套 Java Web 后端实战架构**。为了方便你高效复习与掌握，将这些知识点梳理总结为 **六大核心模块**：



### 一、 网络通信与 HTTP 协议基础

1. **HTTP 协议核心组件**：
   - **请求报文结构**：请求行（方法 + URL + 协议版本）、请求头（Headers）、空行、请求体（Body）。  
   - **响应报文结构**：状态行（协议版本 + 状态码 + 状态描述）、响应头、空行、响应体。  
2. **HTTP 请求方式与 REST 语义**：
   - **GET**：获取资源（数据挂在 URL 后，幂等，有长度限制）。  
   - **POST**：新建资源（数据放在请求体，无限制）。  
   - **PUT**：全量更新资源（数据放在请求体，幂等）。  
   - **DELETE**：删除指定资源（幂等）。  
3. **常见 HTTP 状态码分类**：
   - `200`（成功）、`301/302`（重定向）、`400`（语法/参数错误）、`401`（未认证）、`403`（无权限）、`404`（资源不存在）、`405`（请求方法不允许）、`500`（服务器内部错误）。  

### 二、 Spring MVC 核心接收与响应机制

1. **参数接收五大注解/方式**：
   - **QueryString 参数**：直接形参接收或用 `@RequestParam`（支持映射名改写、`required=true` 校验、`defaultValue` 默认值设置及集合绑定）。  
   - **路径参数 (Path Variable)**：使用 `@GetMapping("/{id}")` + `@PathVariable` 绑定动态 URL 路径中的变量。  
   - **JSON 请求体 (Body)**：使用 `@PostMapping` / `@PutMapping` + `@RequestBody` 将前端传输的 JSON 自动反序列化为 Java 对象。  
   - **实体类自动绑定**：形参声明 POJO，Spring 自动将同名 Query 参数注入对象属性。  
   - **原生 Servlet 对象**：可直接在控制器方法参数中声明 `HttpServletRequest` 或 `HttpServletResponse` 按需获取请求头或写入响应流。  
2. **响应数据处理**：
   - **`@ResponseBody` 与 `@RestController`**：`@ResponseBody` 告知框架将返回值转为 JSON/文本写入响应体；`@RestController` = `@Controller` + `@ResponseBody` 的组合注解。  
   - **通用返回结构 (Result)**：统一定义包含 `code`（状态码）、`message`（提示信息）、`data`（业务数据）的包装类，规范前端解析体验。  

### 三、 架构设计思想（三层架构 & MVC & RESTful）

1. **三层架构 (后端分工策略)**：
   - **表现层 (Controller)**：处理 HTTP 请求接收、入参格式校验、调用业务层并组装统一返回响应。  
   - **业务逻辑层 (Service)**：承上启下，实现具体的业务逻辑规则（如登录校验、重名判断等）。  
   - **数据访问层 (DAO / Repository)**：仅专注与持久化数据源（数据库/内存表）进行 CRUD 交互。  
2. **MVC 设计模式**：
   - 表现层的拆分模式（Model 数据模型 + View 视图/前端 + Controller 调度）。  
3. **RESTful 规范**：
   - 核心原则：**URL 描述资源（纯名词，如 `/user`），HTTP 动作描述操作（GET/POST/PUT/DELETE）**。  

### 四、 Spring 核心容器（IoC / DI）

1. **IoC (控制反转) 与组件管理**：
   - 对象的创建与生命周期交给 Spring 容器统一管理，摒弃手动 `new` 对象。  
   - **组件声明注解**：`@Controller` / `@RestController`（表现层）、`@Service`（业务层）、`@Repository`（数据层）、`@Component`（通用组件）。  
   - **包扫描机制**：默认扫描启动类所在包及其子包，可显式配置 `@ComponentScan`。  
2. **DI (依赖注入)**：
   - **`@Autowired`**：Spring 原生注解，默认按**类型 (byType)** 匹配注入，多实现类时需配合 `@Qualifier("beanName")`。  
   - **`@Resource`**：JDK 原生注解，默认按**名称 (byName)** 匹配注入。  
3. **配置参数注入**：
   - **`@Value("${key:default}")`**：注入单个配置项。  
   - **`@ConfigurationProperties(prefix = "xxx")`**：按前缀批量绑定属性到实体类。  
   - **`@PropertySource`**：加载外部指定的 `.properties` 属性配置文件。  

### 五、 高级扩展与安全防护

1. **声明式异常处理**：
   - 使用 `@RestControllerAdvice` + `@ExceptionHandler(Exception.class)` 拦截全局未捕获异常，屏蔽底层的崩溃堆栈信息，向前端统一返回友好提示 JSON。  
2. **声明式参数校验 (Validation)**：
   - 基于 Jakarta Validation 规范，在实体类属性上标注 `@NotBlank`、`@NotNull`、`@Size`、`@Pattern`、`@Min`、`@Max` 等注解。  
   - 控制器层使用 `@Valid` 开启校验，通过 `BindingResult` 捕获并加工错误提示。  
3. **拦截器 (HandlerInterceptor)**：
   - 实现 `preHandle`、`postHandle`、`afterCompletion` 生命周期生命节点。  
   - 配置类加 `@Configuration` 并实现 `WebMvcConfigurer`，调用 `addInterceptors` 指定拦截路径（如 `/user/**`）与放行路径（如 `/auth/login`、静态资源）。  
   - **登录保护实战**：未登录请求在 `preHandle` 拦截，并直接回写 JSON 响应（如 HTTP/Code `501`）引导跳转。  

### 六、 标准后端代码开发落地顺序

开发一个完整 Web 功能模块的工程化顺序如下：



1. **环境与配置**：创建项目包结构，编写 `pom.xml` 依赖与 `application.properties`。  
2. **公共基础**：定义统一响应类 `Result`，创建 `Entity` / `DTO` 并配置校验注解。  
3. **DAO 持久层**：定义 `UserDao` 接口并实现 `UserDaoImpl`（标注 `@Repository`）。  
4. **Service 业务层**：定义 `UserService` 接口并实现 `UserServiceImpl`（标注 `@Service`，`@Autowired` 注入 DAO）。  
5. **Controller 控制层**：编写 `UserController` 和 `LoginController`（标注 `@RestController`，`@Autowired` 注入 Service，使用 `@Valid` 校验入参）。  
6. **拦截器与安全**：编写 `LoginProtectInterceptor` 拦截未登录访问，并由 `WebMvcInterceptorConfig` 注册生效。  
7. **全局异常兜底**：配置 `@RestControllerAdvice` 进行统一异常拦截。
